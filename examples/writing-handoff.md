# 写作任务接力：完整本地模拟

> 这是虚构案例，用于验证 `task-relay` 的工作流。它没有启动第二个真实智能体，也没有访问任何外部聊天平台，因此属于**本地模拟**，不是跨智能体集成测试。

## 1. 半成品任务输入

当前用户要求：写一篇面向社区居民的 800–1000 字科普稿，主题是“如何识别暴雨预警并准备家庭应急包”；语气平实，不制造恐慌；必须包含四级预警含义、应急包清单和暴雨当天的行动建议。

可检查的半成品 `draft-v1.md` 只有 430 字，已写完开头和四级预警，尚缺应急包清单、行动建议和结尾。一次人工检查确认四级预警顺序正确，但未检查全文字数和措辞。以下内容均为案例设定，不代表工作区内存在该文件。

## 2. 动作 A：生成交接

生成的 `handoff.md` 核心内容如下：

```markdown
# Task handoff

> Updated: `2026-04-12T15:20:00+08:00`
> Task ID: `demo-writing-001`

## Goal
完成一篇面向社区居民的 800–1000 字暴雨预警与家庭应急科普稿。

## Acceptance criteria
- 全文 800–1000 字。
- 包含四级预警含义、应急包清单、暴雨当天的行动建议。
- 语气平实，不制造恐慌。

## State

### Verified complete
- 四级预警段落顺序正确 — Evidence: 人工检查记录 `review-note-1` — Artifact version: `draft-v1` — Verification scope: 仅四级预警段落

### Implemented but unverified
- 开头已写入 `draft-v1.md`，尚未检查语气和事实表述。

### Incomplete
- 补写应急包清单、行动建议和结尾；完成后检查全文字数与语气。

## Material gaps or conflicts
- 无法访问原聊天平台；要求来自用户提供的任务摘要。

## Next action
**Action:** 在 `draft-v1.md` 后补写三个缺失部分，形成 `draft-v2.md`。
**Complete when:** 三部分齐全，全文达到 800–1000 字，且完成一次全文检查。
**Prerequisites:** 无。
```

## 3. 动作 B：新智能体读取并恢复

模拟的新智能体读取交接包和 `draft-v1.md` 后，先给出简短恢复说明：

> 已恢复目标：完成 800–1000 字社区科普稿。可靠断点是 `draft-v1`：四级预警段落经限定范围人工检查，开头仍待核实；缺少的三个部分明确，无权限或材料阻塞。我将从补写应急包清单开始，完成后检查全文结构、字数和语气。

它没有声称访问原平台，也没有把只检查过一个段落理解为全文已验证。

## 4. 继续完成

模拟的新智能体在原稿后续写，例如：

> 家庭应急包不必追求复杂，先准备饮用水、即食食品、常用药、手电筒、备用电池、充电宝、简易雨具、纸巾和重要联系人清单。家中有婴幼儿、老人或慢性病患者时，再补充奶粉、护理用品和足量处方药。证件原件不宜反复搬动，可准备防水复印件，并把应急包放在全家都知道、容易拿到的位置。
>
> 暴雨当天应减少不必要外出，及时关注当地权威预警和道路信息。不要进入积水地下空间，也不要贸然穿过水流较急的路段。车辆遇到深水时，不应强行通行；室内若出现进水或用电风险，应在确保安全的前提下切断电源，并按社区或应急部门指引转移。预警的意义不是让人恐慌，而是把准备做在风险到来之前。

随后它将版本更新为 `draft-v2`，检查必需段落、字数范围和语气；只有这些检查通过后，才把全文列入 `completed`。若统计结果只有 760 字，则应继续列为 `unverified` 或 `remaining`，而不能因为“正文已写完”就宣称任务完成。

## 5. 更新后的接力点

达到检查通过的节点后，两个交接文件同步更新：

- `artifacts` 指向 `draft-v2.md`，旧检查仍明确只适用于 `draft-v1` 的预警段落；
- 新增全文结构、字数和语气检查的时间、范围与结果；
- `remaining` 变为空列表；
- `next_action` 改为“向用户交付草稿并说明检查结果”，但“已经发送”只有在发送动作可核实时才可记录为完成。

这完成了“生成交接 → 读取恢复 → 继续执行 → 更新接力点”的本地模拟闭环。
